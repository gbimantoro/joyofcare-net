1. Executive Summary

Joy of Care adalah platform home healthcare Indonesia (Jakarta/Tangerang/BSD). Proyek ini memiliki dua repositori: joyofcare-net sebagai content master (137 artikel final .txt + strategi + script) dan joyofcare-web sebagai site (HTML statis yang seharusnya di-deploy ke Cloudflare Pages new.joyof.care).

✅ Yang Sudah Bagus

  • 137 artikel final (37 overhauled + 100 new) sudah ditulis ulang gaya Kompas, frontmatter + markdown rapi di joyofcare-net.
  • 168 halaman artikel HTML sudah ter-generate di pages/blog/<kategori>/ — bebas markdown mentah, heading sesuai standar (Penting dipahami), CTA WhatsApp ada di 168/168 file.
  • Dokumen strategi lengkap: SEO-GEO-AIO audit, keyword top-20, content calendar, technical audit, UI/UX review, category mapping, publishing SOP.
  • Kategori 12 aktif dengan distribusi wajar; kualitas artikel 800–1.400+ kata.
  • Script pipeline scripts/build_articles.py (txt → HTML) sudah berfungsi.

🔴 Yang Rusak / Belum Selesai

  • TIDAK ADA deployment produksi yang hidup. new.joyof.care → 404 di semua path; new-joy-of-care.pages.dev tidak resolve; www.joyofcare.net masih menyajikan Odoo lama.
  • Kekacauan arsitektur: 3 stack dalam 1 repo (static HTML + Astro MDX + Next.js/Keystatic CMS) — Astro build GAGAL (YAML rusak), CMS tidak terpakai.
  • Canonical & sitemap drift: artikel → new.joyof.care, hub/sitemap/robots/llms → www.joyofcare.net; sitemap berisi URL Odoo lama yang tidak ada.
  • Kualitas HTML artikel: 164/168 punya 2× H1; FAQPage schema 0/168; datePublished ISO tidak ada; URL WhatsApp ganda ?phone…?text= (168 file).
  • Kedua repo kotor: web 179 file & net 141 file termodifikasi TIDAK di-commit — berisiko hilang.
  • Hub index.json basi: hanya 37 entri vs 168 artikel; hub hanya menautkan 4 kategori lama.
  • Token GitHub (PAT) tertanam di URL remote kedua repo — risiko keamanan.
Verdict keseluruhan: Konten (99%) dan pipeline HTML (85%) hampir siap, tetapi rantai penerbitan putus di mata rantai terakhir — deployment. Tidak ada satu pun halaman yang bisa diakses publik di domain target. Pekerjaan "selesai" versi tim ≠ situs hidup. Ini pola yang sama dengan insiden markdown sebelumnya: laporan ≠ kenyataan; verifikasi eksternal wajib.

5. Status Live / Deployment — MASALAH UTAMA

Fakta terverifikasi via curl/DNS (2026-09-06 07:30 WIB):
  • https://www.joyofcare.net/ → HTTP 200 konten Odoo (cookie frontend_lang/session_id) — situs lama masih hidup di domain utama.
  • https://new.joyof.care/ → HTTP 404 di semua path termasuk /index.html, /blog/, /css/style.css.
  • https://new-joy-of-care.pages.dev/ → tidak resolve (curl exit 6).
  • npx astro build → gagal (YAML error di src/content/articles). Static site di pages/ TIDAK dibangun lewat Astro.
  • Cache lokal wrangler ada (.wrangler/state, terakhir 5 Sep 20:20) — indikasi pernah dicoba deploy/dev secara lokal, tidak ada bukti deploy produksi berhasil.

Akar masalah deployment

  1. Dua pipeline bersaing: static pages/ (yang berisi konten benar) vs Astro src/ (yang gagal build). Cloudflare Pages mungkin dikonfigurasi mem-build Astro (npm run build → astro build) → selalu gagal → deployment tidak pernah sukses → domain 404.
  2. DNS/domain tidak pernah diselesaikan: instruksi user "ubah joyofcare.net dari joyofcare.odoo.com ke pages.dev" tampaknya belum tuntas; www.joyofcare.net masih proxied ke Odoo.
  3. Canonical setengah-setengah: artikel diarahkan ke new.joyof.care, sisanya ke www.joyofcare.net.
  4. Tidak ada verifikasi pasca-deploy (curl) dalam alur kerja tim — "done" berdasarkan laporan, bukan kenyataan. Pola yang sama dengan insiden markdown 3×.
